# Data Schema Reference

This document defines the core data structures used throughout Aegis-AI for telemetry events, Indicators of Compromise (IOCs), Intelligence Layer output models, and the MongoDB document schema.

---

## 1. Telemetry Event Schema

All events generated by the sandbox wrapper (`sandbox/local_sandbox.py`) and transmitted over Redis PubSub conform to the following JSON schema.

### Base Structure

```json
{
  "type": "EVENT_TYPE",
  "severity": "high | medium | info",
  "timestamp": "2026-06-13T14:30:00.000Z",
  "data": {
    // Event-specific payload
  }
}
```

### Event Type Reference

| Type | Severity | Trigger | `data` Fields |
|---|---|---|---|
| `PROCESS_CREATE` | High | External OS-level executable spawned | `pid`, `ppid`, `executable`, `cmdline` |
| `EXECUTION` | High | Dynamic code execution or module loading | `pid`, `cmdline` |
| `FILE_WRITE` | Medium | File handle opened with write/append/create (excluding `.pyc`) | `pid`, `target` |
| `FILE_READ` | Low | File read operation on sensitive paths | `pid`, `target` |
| `SOCKET_CONNECT` | Medium | Outbound TCP/UDP socket connection established | `pid`, `dest_ip`, `dest_port`, `protocol` |
| `DNS_QUERY` | Medium | Hostname resolution request (ignoring localhost) | `pid`, `query` |
| `HTTP_REQUEST` | Medium | HTTP request intercepted | `pid`, `method`, `url`, `target` |
| `REGISTRY_MOD` | High | Windows registry key created or modified | `pid`, `key`, `value` |
| `EXECUTION_ERROR` | High | Runtime crash or exception during dynamic analysis | `error`, `traceback` |
| `EXECUTION_TIMEOUT` | High | Sandbox reached execution time limit (default 10s) | `timeout_seconds` |
| `STATUS_CHANGE` | Info | Job lifecycle transition | `status` |

### Example Events

**Process Creation**
```json
{
  "type": "PROCESS_CREATE",
  "severity": "high",
  "timestamp": "2026-06-13T14:30:00.000Z",
  "data": {
    "pid": 4124,
    "ppid": 1024,
    "executable": "cmd.exe",
    "cmdline": "cmd.exe /c start evil.bat"
  }
}
```

**Network Connection**
```json
{
  "type": "SOCKET_CONNECT",
  "severity": "medium",
  "timestamp": "2026-06-13T14:30:05.000Z",
  "data": {
    "pid": 4124,
    "dest_ip": "192.168.1.100",
    "dest_port": 443,
    "protocol": "TCP"
  }
}
```

**File Write**
```json
{
  "type": "FILE_WRITE",
  "severity": "medium",
  "timestamp": "2026-06-13T14:30:08.000Z",
  "data": {
    "pid": 4124,
    "target": "C:\\Users\\victim\\AppData\\Local\\Temp\\payload.exe"
  }
}
```

## 2. Indicators of Compromise (IOC) Schema

The `ioc_pipeline.py` service consolidates static strings and runtime events into structured IOC records persisted in MongoDB.

### Structure

```json
{
  "type": "ip | domain | url | sha256 | md5 | command",
  "value": "185.11.23.4",
  "source": "Runtime Telemetry | Static Strings",
  "confidence": "High | Medium | Low"
}
```

### IOC Type Reference

| Type | Description | Example |
|---|---|---|
| `ip` | IPv4 or IPv6 address | `185.11.23.4` |
| `domain` | Registered hostname | `evil-c2.example.com` |
| `url` | Full web address | `https://evil-c2.example.com/exfil` |
| `sha256` | SHA-256 file hash | `a3f2b8c...` |
| `md5` | MD5 file hash | `d41d8cd...` |
| `command` | Suspicious command line argument | `powershell -enc JABz...` |

### Confidence Scoring

| Level | Source | Rationale |
|---|---|---|
| **High** | Runtime actions — actual DNS queries, established socket connections, computed static hashes | Verified by sandbox execution; high-fidelity signal |
| **Medium** | Suspicious but non-network runtime patterns — spawning PowerShell, accessing sensitive file paths | Behavioral indicator without confirmed network activity |
| **Low** | Static string extraction — IP addresses or domains found in binary text | May be false positives from imported libraries or configuration strings |

## 3. Intelligence Layer Output Models

All Intelligence Layer outputs are defined as Pydantic models in `app/analysis/models.py`.

### Capability

```python
class Capability(BaseModel):
    capability: str          # "Credential Access"
    severity: str            # "Low" | "Medium" | "High" | "Critical"
    confidence: int          # 0–100
    evidence: List[str]      # ["Browser Login Data access"]
    mitre_mapping: List[str] # ["T1555.003"]
    attack_goal: str         # "Credential Access"
```

### BehaviorChain

```python
class BehaviorChain(BaseModel):
    chain_name: str     # "Infostealer Chain"
    severity: str       # "Low" | "Medium" | "High" | "Critical"
    confidence: int     # 0–100
    evidence: List[str] # Aggregated from constituent capabilities
    attack_goal: str    # "Information Theft"
```

### ThreatClassification

```python
class ThreatClassification(BaseModel):
    family: str         # "Infostealer" | "RAT" | "Ransomware" | ...
    confidence: int     # 0–100
    evidence: List[str]
```

### ImpactAssessment

```python
class ImpactAssessment(BaseModel):
    confidentiality: str  # "Low" | "Medium" | "High" | "Critical"
    integrity: str
    availability: str
```

### RiskAssessment

```python
class RiskAssessment(BaseModel):
    score: int                      # 0–100
    severity: str                   # "LOW" | "MEDIUM" | "HIGH" | "CRITICAL"
    confidence: int                 # 0–100
    verdict: str                    # Threat family or "Suspicious" / "Benign"
    score_breakdown: Dict[str, float]
    reasoning: List[str]
```

### AnalystReport

```python
class AnalystReport(BaseModel):
    executive_summary: str
    technical_findings: List[str]
    threat_classification: ThreatClassification
    mitre_coverage: List[str]
    impact_assessment: ImpactAssessment
    recommended_actions: List[str]
    risk_assessment: RiskAssessment
```

## 5. Neo4j Graph Schema

The attack graph stores relationships between analysis artifacts as a directed graph.

### Node Types

| Label | Properties |
|---|---|
| `SandboxJob` | `job_id`, `status`, `created_at` |
| `File` | `sha256`, `filename`, `size`, `entropy` |
| `Process` | `pid`, `ppid`, `executable`, `command` |
| `NetworkConnection` | `ip_address`, `port`, `protocol` |
| `DnsQuery` | `domain` |
| `IOC` | `type`, `value`, `confidence` |
| `MitreTechnique` | `technique_id`, `name`, `tactic` |
| `YaraRule` | `rule_name`, `category` |

### Relationship Types

| Relationship | From → To | Description |
|---|---|---|
| `ANALYZED` | SandboxJob → File | Job analyzed this file |
| `SPAWNED` | SandboxJob → Process | Job spawned this process |
| `CONNECTED_TO` | Process → NetworkConnection | Process opened network connection |
| `RESOLVED` | Process → DnsQuery | Process performed DNS resolution |
| `EXTRACTED` | SandboxJob → IOC | IOC extracted from this job |
| `MAPPED_TO` | SandboxJob → MitreTechnique | Behavior mapped to this ATT&CK technique |
| `MATCHED` | File → YaraRule | File matched this YARA rule |
